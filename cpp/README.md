# Тестовая программа Qt/C++ — сервер + имитатор устройства (большие данные)

Находится в каталоге `cpp/`:

| Файл | Назначение |
|---|---|
| `protocol.h` | Двоичный TLV-протокол: `MAGIC(2) | TYPE(1) | LENGTH(4, BE) | PAYLOAD`. Типы кадров: Handshake, Meta, Data, Bye, Ack. Потоковый парсер кадров с защитой от битых данных. |
| `server.cpp` | **Сервер** (Qt6, QtCore+QtNetwork, без GUI): слушает TCP-порт, принимает несколько устройств одновременно, читает поток через `readAll()` + инкрементальный парсер, считает статистику (пакеты/байты/Мбит·с), по желанию анализирует float32-массивы (mean/min/max/RMS), шлёт периодические ACK. |
| `client_sim.cpp` | **Имитатор устройства**: N потоков (`QThread`), каждый генерирует большие массивы float32 (гармоники 1/7.5/23 кГц + шум, как сигнал с АЦП) и потоково отправляет серверу. |
| `CMakeLists.txt` | Сборка CMake (AUTOMOC включён). |
| `qt_device_test.pro` | Альтернативная сборка qmake. |

## Требования
* Qt 6 (пакеты `qt6-base-dev` или официальный installer), компилятор C++17, CMake ≥ 3.16.

## Сборка
```bash
cd cpp
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j4
```
или через qmake:
```bash
qmake6 qt_device_test.pro && make -j4
```

## Запуск
Терминал 1 (сервер):
```bash
./build/device_server --port 9000            # приём + статистика
./build/device_server --port 9000 --analyze  # + анализ содержимого пакетов
```
Терминал 2 (имитатор устройства):
```bash
./build/client_sim --packets 100 --packet-size 4MB              # 1 устройство, 419 МБ
./build/client_sim --packets 50  --packet-size 8MB --clients 4  # 4 устройства, ~1.7 ГБ
./build/client_sim --packets 1000 --packet-size 1MB --interval 10  # темп АЦП 100 пакетов/с
```

### Параметры клиента
`--host`, `--port`, `--packet-size` (1MB/4MB/512KB…), `--packets N`, `--clients N` (одновременные устройства), `--interval MS` (пауза между пакетами), `--sample-rate HZ`.

### Параметры сервера
`--port`, `--ack-interval-ms` (частота подтверждений), `--analyze` (mean/min/max/RMS по каждому пакету).

## Проверенные прогоны (реальные результаты)
* 100 × 4 МБ, один клиент, `--analyze`: сервер принял все пакеты,
  `DEV-001: DATA seq=0 n=1048575 mean=0.0002 min=-1.242 max=1.248 rms=0.6088` —
  RMS соответствует синтетическому сигналу; ACK доходят до клиента.
* 4 клиента × 50 × 8 МБ = 1677.7 МБ суммарно: сервер посчитал по 50 пакетов на каждое
  устройство, потерь нет.

## Как это работает
1. Клиент шлёт `Handshake` (id/model/fw/частота) и `Meta` (JSON).
2. Затем потоком кадры `Data`: `seq(4) + float32[~N]`, размер кадра — мегабайты.
   Сервер читает сокеты асинхронно (`readyRead` → `readAll`), поэтому многомегабайтный
   кадр arrives кусками и собирается парсером; память под кадр выделяется один раз.
3. Каждую секунду сервер отвечает `ACK` (сколько пакетов/байтов принято) — клиент
   сверяет и печатает подтверждение.
4. В конце `Bye` — сервер печатает итоговую сводку по сессии.

Для продакшена здесь есть точки расширения: вынос анализа в `QtConcurrent`/отдельный
поток, запись сырых данных в файл (`.bin`/HDF5), переход на UDP-мультикаст для
широковещательных АЦП-потоков.
