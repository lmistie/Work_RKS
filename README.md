# Work_RKS

## Тестовая программа: сервер + имитатор устройства с большими массивами данных

Набор для тестирования приёма **больших объёмов данных** от клиента (устройства) к серверу по TCP.

### Файлы

| Файл | Назначение |
|---|---|
| `protocol.py` | Общий двоичный протокол кадров (MAGIC + TYPE + LENGTH + PAYLOAD) |
| `server.py` | Сервер на `asyncio`: принимает кадры, обрабатывает большие массивы в отдельном процессе-воркере (`multiprocessing.Pool`), считает статистику, шлёт ACK |
| `client_sim.py` | Имитатор устройства: генерирует синтетический сигнал float32 (гармоники + шум) и потоково отправляет его на сервер |

### Протокол

```
+--------+--------+-----------------+------------------+
| MAGIC  | TYPE   | LENGTH (uint32) | PAYLOAD          |
| 2 б    | 1 б    | big-endian      | LENGTH байт      |
+--------+--------+-----------------+------------------+
```

Сообщения: `HANDSHAKE (0x01)` → `META (0x03)` → поток `DATA (0x02)` → `BYE (0x04)`;
сервер отвечает `ACK (0x81)` на handshake и периодически — со счётчиком принятых пакетов.

Payload пакета данных: `seq (uint32) | timestamp_ns (uint64) | chunk (сырые float32)`.

### Быстрый старт

```bash
pip install numpy

# Терминал 1 — сервер:
python -u server.py --port 9000

# Терминал 2 — имитатор устройства (100 пакетов × 1 МБ ≈ 100 МБ):
python client_sim.py --port 9000 --packets 100 --packet-size 1MB
```

### Примеры нагрузочных тестов

```bash
# Один поток, крупные пакеты (4 МБ), всего ~256 МБ
python client_sim.py --packets 64 --packet-size 4MB

# 4 «устройства» одновременно, суммарно ~1 ГБ
python client_sim.py --clients 4 --packets 64 --packet-size 4MB

# Имитация реальной скорости АЦП: пакет 2 МБ каждые 50 мс
python client_sim.py --packets 100 --packet-size 2MB --interval 0.05

# Сервер с бо́льшим числом процессов-обработчиков
python server.py --port 9000 --workers 4
```

### Что делает сервер при получении большого массива

1. Читает кадр из сокета (не блокируя event loop).
2. Кладёт payload в очередь `multiprocessing.Pool` — аналитика
   (`np.frombuffer` → mean / peak / RMS) выполняется **в отдельном процессе**
   и не тормозит приём следующих пакетов.
3. Раз в секунду шлёт клиенту ACK со счётчиком и печатает статистику:
   пакеты, мегабайты, Mbit/s.

  [+] Подключение: ('127.0.0.1', 55026)
      handshake: устройство #1 'sim-device-1'

Все 100/100 пакетов дошли, статистика сигнала корректна (синус r≈0.797 = sqrt(1²+0.5²)/√2 + шум).

### Возможные расширения

- Целостность: добавить CRC32 в кадр (`zlib.crc32`) и сверять на сервере.
- Сжатие payload (`lz4`/`zstd`) для экономии канала.
- Сохранение принятых массивов на диск (`.npy` / HDF5) — легко добавить в `process_chunk`.
- Переход на UDP/RDMA-подобную схему для экстремальных скоростей (>10 Gbit/s).
